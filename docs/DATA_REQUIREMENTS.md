## Study boundary

Supply a GeoJSON, GeoPackage, or ESRI shapefile containing valid Polygon or MultiPolygon features and an explicit CRS. Include `.shp`, `.shx`, `.dbf`, and `.prj` for a shapefile, plus any other companion files. The code reads all features, combines them, and transforms to EPSG:4326 for querying the data cube. Pixel masking takes place on the output raster grid.

Specify a boundary source, version, redistribution terms, and any geometry edits in your research record. The example rectangle in `examples/aoi_demo.geojson` is synthetic and makes no administrative-boundary claim.

## Integration criteria

The CSV must contain these exact headings:

```csv
Trend,State,Performance,Degraded
```

Use Y or N in every cell. Y in an indicator column means that input equals 1; N means it equals 0. Each of the eight distinct combinations must occur once. Degraded is the final 1/0 result encoded as Y/N.

`examples/criteria_template.csv` lists all scenarios with a blank Degraded column for the researcher to complete. It intentionally fails validation until filled. `examples/criteria_any_indicator_example.csv` is a working **illustration** that marks a pixel degraded if any input is 1. The original study's decision rule cannot be inferred from the notebooks or their aggregate area summaries.

## Raster conventions

- Monthly files: `ndvi_roll3_YYYYMM_<file_version>.tif`, one single-band float NDVI raster per month.
- Annual files: `ndvi_annual_<annual_metric>_YYYY.tif`, one single-band raster per year.
- Rasters must share CRS, affine transform, width, and height before pixelwise analysis.
- Default NDVI outputs use floating values, not NDVI×10,000 integers; keep the performance scale factor at 1.0 for these outputs.
- Nodata differs by product: monthly/annual/continuous trajectory use NaN; state Z and performance use −9999; categorical outputs use 255 or −128 as documented in METHODS. Read the source metadata rather than assuming a universal nodata value.

## Data archiving for reproduction

Keep the AOI and criteria, configuration snapshot, software-version record, processing logs, code commit/release, and product provenance with each analysis. Archive important outputs with checksums and a persistent identifier. If only code is published, distinguish a reusable workflow from an exactly reproduced research result. Data licences apply separately from the code licence.
